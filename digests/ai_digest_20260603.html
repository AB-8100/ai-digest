📐 ML & Technical Fundamentals

Topic: Retrieval-Augmented Generation (RAG) in Production — What's Changed in 2026

RAG has become the default architecture for enterprise AI deployments that need to ground model outputs in proprietary data. The pattern is straightforward: instead of fine-tuning a model on your internal knowledge, you retrieve relevant documents at query time and pass them as context. But production RAG is harder than demos suggest.

The 2026 enterprise AI stack is often built around a combination of Vertex AI, GKE, and specialised RAG pipelines to ensure model responses are tied to proprietary company truth — alongside vector databases for grounding AI in internal PDFs and small language models for efficient processing of internal data. The key architectural decision in 2026 is not which vector database to use, but how to handle retrieval quality: naive semantic search using cosine similarity on embeddings fails when documents are long, queries are ambiguous, or the knowledge base is large. Hybrid search (combining dense embeddings with BM25 sparse retrieval) has become standard.

For 42% of enterprise implementations, model choice was fully interchangeable — companies don't always need the best available AI models. The durable advantage is in the orchestration layer, not the foundation model. This is a useful reframe for clients who want to start with "which model should we use?" — the smarter question is "what does our retrieval pipeline look like?"

Recent development: Anthropic's Natural Language Autoencoders paper (May 7, 2026) explores turning Claude's intermediate representations into text — relevant for interpretability in RAG systems where understanding why a model retrieved a particular chunk matters for debugging.

🔬 Technical Deep Dive: Speculative Decoding — Now Production Standard

Speculative decoding has moved from a 2022 Google research paper to infrastructure that most serious LLM serving frameworks now implement by default. It's worth understanding because inference cost is increasingly the constraint on which AI features get shipped.

The core insight is about where the bottleneck in LLM inference actually sits. The GPU compute units are waiting for weights to load from memory, not running out of arithmetic capacity. LLM inference clusters at arithmetic intensity near 1 FLOP per byte — deep in the memory-bound region. The GPU sits mostly idle, waiting on data. Speculative decoding exploits this waste: if you are paying the memory bandwidth cost per step anyway, you might as well verify several tokens per load rather than one.

The mechanism: speculative decoding is an inference-time optimisation that speeds up LLM token generation without reducing output quality. A smaller, fast "draft" model proposes several tokens ahead. A larger target model verifies these proposed tokens in parallel and accepts those that match its own predictions. This draft-then-verify pattern guarantees the final output matches exactly what the original target model would have produced — it does not sacrifice output quality.

The practical result: benchmarking has demonstrated a 3.87x speedup over standard autoregressive generation, reducing inference time from 136 seconds to 35 seconds, with a draft model acceptance rate of 84%. In production, gains of 2–3x are typical, depending on how well the draft and target models are aligned on the specific task distribution.

What's changed in 2026 is adoption: speculative decoding is now default in vLLM, SGLang, and TensorRT-LLM. The more recent variants — EAGLE3 and Medusa — use learned draft models that share the target model's hidden states, achieving higher acceptance rates than independent draft models. The new Speculative Decoding Scaling Laws paper (arXiv 2603.11053) provides a theoretical framework for predicting optimal draft model size before training, removing trial-and-error from deployment. For AI PMs at consulting firms: understanding speculative decoding matters when advising clients on inference infrastructure choices — it's one of the few optimisations that reduces latency and cost without touching model quality.

Key resources: Google's original 2022 paper, Prem AI 2026 explainer, SDSL scaling laws paper.
